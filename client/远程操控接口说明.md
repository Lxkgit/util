# 远程操控接口与信令约定

服务端地址：`http://124.221.195.130`

## 设备注册

- 方法：POST
- 路径：`/api/file/client/register`
- Content-Type：application/json
- JSON 必须包含 `key`。
- 客户端提交完整设备 JSON；服务端按设备 key 保存。

注册数据示例：

```json
{
  "key": "客户端本地生成并持久化的唯一标识",
  "deviceName": "Windows 主机名",
  "platform": "Windows 版本信息",
  "version": "1.0.0",
  "signals": []
}
```

## 心跳

- 方法：GET
- 路径：`/api/file/client/heartBeat?key={key}`
- 客户端每 60 秒发送一次。
- 服务端 Redis TTL 为 300 秒。
- 关闭“允许本机被发现”后停止心跳，服务端记录等待 TTL 自然过期。

## 在线设备列表

- 方法：GET
- 路径：`/api/file/client/list`
- 客户端每 5 秒轮询。
- 响应的 `result` 是 JSON 字符串数组，客户端逐条反序列化。

## WebRTC 信令

服务端不解析信令。客户端将信令消息追加到自己的设备 JSON 的 `signals` 数组，再调用注册接口覆盖更新自身 JSON。

每条信令包含：

- `messageId`：消息唯一 ID
- `from` / `to`：发送和接收设备 Key
- `type`：目前使用 `offer`、`answer`
- `payload`：SDP 内容
- `createdAt` / `expiresAt`：消息创建和过期时间

第一版使用完整 SDP（非 Trickle ICE），由 STUN 收集候选地址，不使用 TURN。信令有效期为 180 秒。

## P2P 业务

DataChannel 只开放：

- `get_software_list`：读取 Windows 卸载注册表中的已安装软件。
- `capture_screen`：截取远端主显示器，JPEG 分块传输。

不提供 Shell、PowerShell、任意代码执行、鼠标或键盘控制。

## 安全和网络限制

1. 被访问端收到连接请求后必须在本机确认。
2. 接受连接后，对端可在本次会话中请求软件列表和屏幕截图。
3. 当前服务端使用 HTTP，信令内容没有端到端身份认证；设备 Key 只是标识，不是认证凭证。此版本适合受控测试，不应在不可信网络中作为正式远程访问工具使用。
4. STUN 只能辅助 NAT 穿透。双方网络若无法建立直连，会连接失败；当前不配置 TURN，也不通过业务服务器中继。
5. 注册接口会覆盖完整设备 JSON；客户端发布信令时会保留本机尚未过期的信令。心跳接口只刷新 TTL，不修改 JSON。
